Purpose

Add persistent meta progression safely to math_game_v2 without destabilizing current Classic gameplay, frozen round history, or session/round state boundaries.

Core economy roles

Gold

session-scoped

main score currency during session

later usable only in end-of-round merchant for weak/cosmetic rewards

Gems

session-scoped

tactical in-round store currency

not persistent

Diamonds

persistent across sessions

manually awarded by admin

used for long-term progression

first use: permanent upgrades only

Gear

later persistent item layer

weaker than permanent upgrades

not in first Diamonds implementation

Product rules
Persistent ownership

Player is the persistent identity anchor

persistent progression data must not live in PlayerWallet or other session-scoped tables

Diamond spending

Diamonds cannot be spent during active session flow

Diamond shop is only available outside an active session lifecycle

Upgrade timing

Persistent upgrades are resolved into frozen round-effective values at round start

They do not change mid-round

Lobby or between-round changes do not affect the already-started round

Gold merchant timing

Gold merchant is a separate future system

It appears after round end only

It does not sell permanent upgrades

History integrity

Round history remains frozen at round end

Persistent progression must never mutate historical round results

Add

PlayerUpgrade persistent upgrade ownership table

Notes

Why first

Phase D3 — round-start snapshot resolution [COMPLETE — 9 tests + 19 stock clarity tests]
Goal

Freeze persistent upgrade effects into round-specific values.

Scope

at round start, resolve each player’s persistent upgrades into round-effective values

store one frozen row per player per round

no live gameplay lookups from persistent upgrade tables during action handling

Effective values to snapshot

effective steal token capacity

effective mine bonus

effective treasure bonus

effective shield percentage bonus

Formula rules

shield bonus is percentage-based from round config

it affects both manual and reactive shield durations

future gear flat bonus will stack after percentage calculation

Why fourth

This preserves determinism and prevents mid-round mutation.

Phase D4 — gameplay wiring [COMPLETE — 20 tests + 11 treasure side-reward tests + 9 D4b unified SC tests; migrations d4a1b2c3e4f5, d4b1a2b3c4d5]
Goal

Make gameplay use only frozen round-effective values.

Scope

Wire frozen values into:

mine reward calculation

treasure reward calculation

steal token capacity enforcement

manual shield duration

reactive shield duration

Rules

do not read persistent upgrade tables in action handlers

read only frozen round-effective snapshot for the current round

Why fifth

This is the first gameplay-changing step and should happen only after the model, wallet, ledger, and shop are stable.

Phase D5 — QA and hardening [COMPLETE — 10 tests + ~22 stabilization tests; migration d5a1b2c3d4e5]
Goal

Must-test cases
