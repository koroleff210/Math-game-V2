DATA/MIGRATION POLICY (IMPORTANT)
---------------------------------
Before coding, inspect the real Topic model/schema and identify the existing legacy subject string field
(whatever its actual field name is in the repo).

Use that real field for backfill.

Backfill rules:
- null / blank / whitespace-only legacy values = no Subject row, no subject_id assignment
- trim leading/trailing whitespace
- collapse repeated internal whitespace if needed
- dedupe conservatively
- case-insensitive dedupe is acceptable
- preserve a clean display name for Subject.name
- do NOT use fuzzy matching
- do NOT merge semantically similar but non-identical values
- examples:
    "Math", " math ", "MATH"  -> may map to one Subject
    "Physics" and "Physics HL" -> must NOT be merged automatically

Transitional rules:
- keep the legacy topic subject string field unchanged
- do NOT remove or rename it
- do NOT make subject_id required
- do NOT break pages that still rely on legacy/fallback display logic

If the repo unexpectedly does NOT contain a usable legacy topic subject string field:
- still implement Subject + Topic.subject_id + admin integration
- skip backfill cleanly
- report this explicitly in the final summary
